# ماتریس پذیرش و شواهد برای تحویل امشب

مرجع: [برنامه](ROADMAP-MAX-SCORE-fa.md) و [backlog](EXECUTION-BACKLOG-fa.md). این فایل طراحی آزمون است و ادعا نمی‌کند آزمون‌ها اجرا یا پاس شده‌اند. هر سناریو در اجرا باید expected IDs/sets و constraintها را از دادهٔ واقعی بگیرد؛ ID تازه برای آسان‌کردن دمو نسازید.

## ۱. قواعدی که شکست حتی یک موردشان مانع «پاس کامل» است

| ID | invariant | روش مشاهده/آزمون |
|---|---|---|
| V01 | تمام product/shop/offer IDها واقعی و رابطه‌ها درست | resolve مجدد خروجی سرویس/API/کارت در DB؛ ورودی ناموجود باید رد شود |
| V02 | بودجه، شعاع، پرداخت و زمان اجباری بی‌اجازه تغییر نکنند | خروجی هر گام و event با آخرین preferences/version مقایسه شود |
| V03 | simulation هرگز تأیید واقعی/رزرو معرفی نشود | assertion محتوای entry/progress/result/visit و screenshot نهایی |
| V04 | قیمت/ساعت/ETA/گارانتی/مشخصات از evidence یا unknown بیاید | قطع سرویس/فیلد خالی؛ عدم وجود مقدار ثابت ساختگی |
| V05 | پاسخ قدیمی و event کاربر دیگر اعمال نشود | edit/reset در حین run، دو browser context، refresh/restart |
| V06 | ناشناختهٔ پرداخت/ساعت، قبولی قید اجباری محسوب نشود | fixture unknown در policy و UI؛ بررسی امکان انتخاب verification صریح |
| V07 | نتیجهٔ شبیه‌ساز دادهٔ اصلی را overwrite نکند | مقایسهٔ offer و checksum دادهٔ خام قبل/بعد؛ event مستقل |
| V08 | متن فروشنده/OCR/review اختیار تغییر شرط یا تماس نداشته باشد | fixture injection و بررسی state/tool/action و نبود افشای credential |

حقیقت hard constraint و ID باید ۱۰۰٪ پاس شود. موفقیت task و کیفیت retrieval جدا سنجیده شوند؛ یک توضیح زبانی خوب، خروجی نامعتبر را پاس نمی‌کند.

## ۲. چهل سناریوی برچسب‌دار اصلی

۲۸ سناریو برای توسعه و ۱۲ سناریو، دو نمونه از هر گروه، برای held-out نهایی کنار گذاشته شوند. held-out برای انتخاب alias/تنظیم ranking مصرف نشود. انتخاب دو نمونهٔ هر گروه در شروع اجرا ثبت شود. دادهٔ تست از IDs موجود و fixtureهای محدود لبه‌ها تشکیل شود؛ عرضهٔ fixture ساختگی به کاربر به‌عنوان دیتاست مجاز نیست.

## ۳. آزمون‌های مکمل؛ علاوه بر ۴۰ سناریو

- API: آفر/shop ناموجود، ID واقعی با رابطهٔ اشتباه، مبلغ دستکاری‌شده/منفی/NaN، role نامعتبر و session دیگر؛ همه باید رد یا به خطای قابل استفاده تبدیل شوند.
- وضعیت: دو session، refresh، restart، redeploy، دو کلیک، cancel و پاسخ دیررس؛ عدم اختلاط، duplication و از دست‌رفتن event.
- منبع/شبیه‌سازی: قیمت recorded و observed، زمان تغییر قیمت و زمان بررسی، badge در تمام مراحل، عدم ادعای reserve و قطعی‌بودن.
- صوت: چهار فایل/utterance فارسی با رقم/مدل لاتین؛ ویرایش؛ denial/unsupported/stop/cancel؛ عدم متن mock.
- تصویر: مدل واضح، تصویر دسته‌ای مبهم، تصویر نامرتبط/اسلاید؛ invalid/oversize؛ cancel و نسخهٔ قدیمی؛ هیچ تصویر خودکار R50i نشود.
- دستور تزریق‌شده: screenshot تغییر بودجه، seller text تأیید ترب‌پی/stock، review درخواست secret، simulator درخواست تماس واقعی؛ اختیار یا افشایی حاصل نشود.
- مرورگر: مسیر کشف، مدل مستقیم، اقساط، recovery و no-result روی ۳۹۰/۱۴۴۰؛ keyboard/focus/zoom و منابع خراب.
- کارایی: مجموعهٔ ثابت حداقل ۲۰ query نماینده، هر کدام پنج بار، warm/cold جدا؛ agent با حداقل ۲۰ run نماینده در محیط مشخص؛ p50/p95، error rate و تعداد نمونه گزارش شوند. هدف‌ها زیر ۱ ثانیه جست‌وجو و زیر ۸ ثانیه پاسخ مفیدند؛ کمبود نمونه یا زمان صریح ثبت شود.
- فشار مختصر: حداقل پنج session هم‌زمان روی داده/چت کنترل‌شده و بررسی event loop/SQLite locks؛ میزان فشارِ دمو اندازه‌گیری شود، نه ادعای مقیاس‌پذیری تولیدی.
- انتشار: health، لینک public در session تازه، اینترنت دوم، فونت/عکس/نقشه/provider از سرور لیارا؛ restart و حفظ داده/چت؛ آخرین نسخه و rollback.

## ۴. مدرک هر محور و تعریف پایان

| محور | مدرک نهایی |
|---|---|
| محصول ۷۵ | Q01–Q16، Q29/Q30/Q37 و مسیر نهایی خرید؛ ویدئوی انتخاب تا مراجعه |
| UX ۷۵ | Q17–Q22، پنج مسیر E2E، تصاویر موبایل/دسکتاپ، ناظر بدون توضیح کد |
| هوشمندی ۵۰ | Q23–Q36، trace ابزار و what-changed، شکست و جایگزین معتبر |
| انتشار ۴۰ | URL HTTPS، health، restart/redeploy، شبکهٔ دوم و release ID |
| فنی ۴۰ | build/typecheck/lint/tests، validation، stale/cancel، latency و مرز untrusted input |
| دیتاست ۲۰ | شمارش/FK، null، چندآفری، semantic پرداخت/ساعت، provenance و timestamp در UI |

هر رکورد نتیجه شامل `case_id، commit، public_url، environment، session_version، input، expected_ids/constraints، observed، pass/fail، duration، evidence_path` باشد. transcript خامِ دارای secret یا media خصوصی ذخیره نشود. نتایج مرز mock، اتصال live و آزمون دستی با برچسب متفاوت ثبت شوند.

یک کار زمانی بسته است که رفتار، آزمون مرتبط، ادغام UI/API و مدرک نسخهٔ واقعی کامل باشند. تکمیل مجموعهٔ چهل‌تایی به‌تنهایی ۳۰۰ امتیاز را تضمین نمی‌کند؛ فرم/ویدئوی اجباری، کیفیت توضیح و قضاوت داور جدا هستند. هر failure با اثر واقعی ثبت شود و هیچ تست اجرا‌نشده پاس معرفی نشود.
