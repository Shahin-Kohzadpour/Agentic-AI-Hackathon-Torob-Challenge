# Backlog اجرایی ادامهٔ پروژه

مرجع: [برنامهٔ زمان‌بندی و اولویت امتیاز](ROADMAP-MAX-SCORE-fa.md). مهلت: ۱ آبان ۱۴۰۵ ساعت ۲۱ تهران؛ freeze قابلیت: ۱۹:۲۰؛ هدف ارسال: ۲۰:۲۰. توسعه‌دهندهٔ تمام ردیف‌ها Codex است؛ وظایف حساب/نظارت/روایت/ارسال انسانی در برنامه مشخص‌اند. این فهرست مجوز یا فرض اجرای چند agent موازی نیست.

وضعیت اولیهٔ همهٔ کارهای ادامه `todo` است. دادهٔ ممیزی‌شده و اجزای موجود، ورودی کارند؛ بسته‌شدن نسخهٔ نهایی به مدرک همان نسخه نیاز دارد. ستون «مسیر» محل اصلی تغییر/بررسی است؛ مسیرهای تازه، پیشنهادند و هنوز ایجاد نشده‌اند. آزمون داخل هر ردیف جزئی از همان کار است، نه وظیفه‌ای که به آخر روز موکول شود.

اولویت: **P0** مانع اعتبار/تحویل؛ **P1** قابلیت اصلی امتیازآور؛ **P2** تکمیل کیفیت الزامی؛ **P3** مکمل پس از عبور هسته. P3 امتیاز رسمی مستقل ندارد و در صورت توقف، ناتمام ثبت می‌شود. ترتیب نمایش خانواده‌ها به‌تنهایی ترتیب اجرا نیست؛ وابستگی‌ها و گروه‌بندی پایین سند ملاک‌اند.

۱. F01/F02/F03؛ هم‌زمان با همین بسته، T01 پایه و D01 آماده شوند. DS01 baseline موجود بررسی سریع شود.

۳. P01/P04، I02/I03، P05؛ U06 برچسب‌ها همراه این مسیر. D02 در اولین build سالم آغاز شود. این، مسیر بحرانی تحویل است.

۴. P02/P03، U01/U02/U03/U04، P06 و I01/I04/I05/U05؛ D03/D05/T05 و خطاهای اتصال حین ادغام بررسی شوند.

۵. اگر دروازهٔ هسته پاس شد، E01/E02 و سپس E03؛ D04 و تکرار DS01 روی انتشار نهایی؛ بستن T01/T04/T05.

۶. R01 → freeze → R02 → R03. تأخیر مراحل قبل، زمان P3 را مصرف می‌کند؛ زمان ارسال ویدئو مصرف توسعه نمی‌شود.

```text
ID:
```
